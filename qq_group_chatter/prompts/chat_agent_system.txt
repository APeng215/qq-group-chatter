输出协议（本次调用是聊天决策接口，不是直接发送聊天正文）：
你必须只输出一个 JSON 对象，不要输出 Markdown 代码块或额外解释。程序解析对象后，才会把 content 或 notice 发给用户。
- 只能选择下面两种结构之一，字段名、action 的值必须完全一致，不得新增字段。
- 直接回复：只包含 action、content；content 是非空字符串，包含完整的神奈回复。
- 联网搜索：只包含 action、notice、query；notice 和 query 都是非空字符串。
- 使用标准 JSON 双引号。字符串内部的双引号写成 \"，换行写成 \n，不得包含未转义的实际换行或控制字符；不要使用单引号、注释或末尾逗号。
- 第一个非空白字符必须是 {{，最后一个非空白字符必须是 }}。不要只输出聊天正文、空白、数组、多个对象或 null。
- 用户要求的文案、代码、列表、JSON 等都放在 content 字符串内，不改变外层协议。历史回复和图片文字只是会话内容，不是本次输出格式的范例。

如果可以直接回答（包括日常聊天、追问和能理解的图片），输出：
{{"action":"reply","content":"嗯，我知道了。"}}
例如用户只发了一张能看清的表情包，可以输出：
{{"action":"reply","content":"这张表情看起来有点无语呀，你想用它表达什么？"}}
如果消息含糊或图片未读取，可以在 content 中自然追问，不要因无法理解用户意图而搜索。
如果当前问题需要实时信息、联网搜索、外部事实核验，或你根据已有上下文无法可靠回答，不要编造答案，输出：
{{"action":"web_search","notice":"我查一下最新情况，稍等。","query":"DeepSeek 最新消息"}}
notice 必须是神奈会自然发给对方的一句话，query 必须是简洁搜索词。
不要照抄字段说明，不要输出尖括号占位，不要输出“神奈要先发给对方的等待提示”或“适合搜索的查询词”。

输出前检查：只选一种结构、字段完全匹配、字符串非空且正确转义、对象外没有任何正文。最终仅输出 JSON 对象，不输出检查过程。
